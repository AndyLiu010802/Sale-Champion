# TV Sales Leaderboard — 设计文档

- **日期**:2026-08-17
- **状态**:已与需求方确认
- **定位**:类 Spinify 的房产销售数据电视展示系统。内部先用,架构预留多租户 SaaS 能力。

## 1. 产品概述

办公室共享电视全天候轮播展示销售数据:游戏排行榜风格的销售榜单、团队目标进度、房源与公告页。新成交录入后,所有电视立即打断轮播,全屏播放庆祝动画 + 该销售员的专属主题曲。管理员通过 Web 后台录入数据、管理销售员与电视屏幕。

**关键决策记录**(需求访谈结论):

| 决策点 | 结论 |
|---|---|
| 产品定位 | 内部先用,预留 SaaS 架构(所有表带 `org_id`) |
| 数据来源 | 手动录入后台优先;预留 CRM 同步适配器接口,未来优先适配 Agentbox |
| 电视接入 | 浏览器 + 6 位配对码(Spinify 模式),无需安装 App |
| 轮播内容 | 销售排行榜、成交庆祝弹屏、团队目标进度、房源/公告页 |
| 排名指标 | 多指标各自成榜、轮播切换:成交套数、佣金总额(GCI)、新增房源 |
| 界面语言 | 英文为主(电视端与后台) |
| 视觉风格 | 电竞霸榜风:深色底 + 霓虹光效 + 金银铜名次高亮 |
| 庆祝音效 | 每位销售员专属主题曲(内置曲库选择或上传),无则播默认曲 |
| 后台账号 | 仅管理员登录,销售员无账号 |
| 部署 | 云端(Railway):Next.js 应用 + PostgreSQL;文件存 Cloudflare R2 |
| 技术架构 | Next.js 全栈单体 + WebSocket 实时推送 |

## 2. 系统架构

单个 Next.js 应用(自定义 Node 服务器)承载三部分:

```
┌─ 电视展示端 /tv ──────────┐   ┌─ 管理后台 /admin ─────────┐
│ 配对码 → 全屏轮播          │   │ 仅管理员登录               │
│ WebSocket 长连接           │   │ 成交/销售员/房源/公告/屏幕  │
└──────────┬───────────────┘   └──────────┬───────────────┘
           │        HTTPS + WebSocket      │
┌──────────┴──────────────────────────────┴───────────────┐
│ Next.js 应用服务器(Railway 部署,单进程)                  │
│  API Routes │ WebSocket Hub │ 轮播配置 │ Auth │ CRM适配器(预留)│
└──────────┬──────────────────────────────┬───────────────┘
   ┌───────┴────────┐            ┌────────┴────────┐
   │ PostgreSQL      │            │ Cloudflare R2    │
   │ 全表带 org_id    │            │ 照片/主题曲/图片   │
   └────────────────┘            └─────────────────┘
```

- **单进程约束**:WebSocket Hub 与 API 同进程,成交录入后直接在内存中广播,无需消息队列。未来横向扩容时再引入 Redis Pub/Sub(明确列为非目标)。
- **CRM 同步适配器**:定义统一接口 `CrmAdapter { fetchAgents(); fetchSales(since); fetchListings(since) }`,MVP 只交付接口定义与手动录入实现,Agentbox 适配器为后续工作。

## 3. 数据模型

所有表含 `id`、`org_id`、`created_at`;金额一律以**分(cents)**存整数。

| 表 | 字段要点 |
|---|---|
| `orgs` | `name`;MVP 种子数据创建单行 |
| `users` | `email`(唯一)、`password_hash`、`name`;均为管理员角色;首个管理员由种子脚本创建 |
| `agents` | `name`、`photo_url?`、`anthem_url?`、`active`(离职置 false,历史数据保留) |
| `sales` | `agent_id`、`address`、`sale_price_cents`、`gci_cents`、`sale_date`、`updated_at`;MVP 一笔成交归一名销售员 |
| `listings` | `agent_id`、`address`、`list_price_cents`、`photo_url?`、`listed_date`、`status`(`active/sold/withdrawn`) |
| `screens` | `name`、`device_token_hash`(唯一)、`pair_code?`(6 位、待配对时有值、15 分钟过期)、`status`(`pending/paired`)、`last_seen_at` |
| `announcements` | `title`、`body?`、`image_url?`、`enabled`、`sort_order` |
| `goals` | `metric`(`sales_count/gci/listings`)、`target_value`、`period`(`month/quarter`)、`active` |
| `settings` | 每 org 单行:启用的轮播页及顺序(JSON)、各页停留秒数、榜单周期(`week/month/quarter/year`,默认 month)、庆祝时长秒数(默认 18,范围 10–30)、音量、`default_anthem_url` |

内置音效曲库为应用内静态资源清单;`agents.anthem_url` 指向内置曲目路径或 R2 上传文件。

## 4. 电视配对与实时机制

**配对流程**:
1. 电视浏览器打开 `/tv`,无本地令牌 → 调用 API 创建 `pending` 屏幕记录,显示 6 位配对码。
2. 管理员在后台输入配对码并命名屏幕 → 服务器置为 `paired`、签发设备令牌,经 WebSocket 推给电视。
3. 电视将令牌存入 localStorage,此后断电重启自动重连,无需重新配对。
4. 后台可对屏幕改名、解绑(令牌立即失效,电视回到配对码界面)、查看在线状态(基于心跳的 `last_seen_at`)。
5. 待配对记录 15 分钟未认领即过期,电视自动换新码。

**WebSocket 事件**(服务器 → 电视):
- `celebration.play`:携带销售员姓名/照片、房源地址、成交价、主题曲 URL
- `data.updated`:携带变更域(sales/listings/goals/announcements/agents),电视端拉取对应数据平滑更新
- `config.updated`:轮播配置变更,电视端即时应用,无需刷新
- `screen.updated` / `screen.unpaired`:改名或解绑
- 心跳 ping/pong,断线后指数退避自动重连

**声音解锁**:浏览器禁止无交互自动播放音频。电视端配对完成后显示"Click to start"启动按钮,单次点击后全屏进入轮播并永久解锁音频。若检测到音频上下文未解锁,持续显示该覆盖层。

## 5. 轮播引擎

- 轮播队列由后台配置:页面启用开关、顺序、每页停留秒数。默认循环:成交套数榜 → GCI 榜 → 新增房源榜 → 团队目标进度 → 房源页 → 公告页。
- 榜单默认当月周期,可配置周/月/季/年;周期起点按自然周期(周一/1 号)自动翻篇。
- 并列名次规则:主指标相同 → 按 GCI 高者优先 → 仍相同按最早成交时间优先。
- 榜单展示前 10 名;前三名金/银/铜霓虹高亮;数据更新时行位置平滑动画过渡,不闪屏。
- 庆祝弹屏优先级最高:打断当前页,播完回到被打断页面的剩余时间继续;多笔成交进入 FIFO 队列依次播放。
- 电视端为单页应用,数据在本地缓存,轮播渲染不依赖每页实时请求。

## 6. 成交庆祝规范

- 触发:仅在成交**创建**时触发;编辑不重播;后台每笔成交提供"Replay celebration"按钮手动重播。
- 画面:全屏霓虹动画(粒子/光效)、销售员照片(无照片显示姓名首字母头像)、姓名、房源地址、成交价。
- 声音:该销售员专属主题曲;未设置则播 `settings.default_anthem_url`;音量取全局设置。
- 时长:默认 18 秒,可配 10–30 秒;结束淡出回轮播。

## 7. 视觉规范(电竞霸榜风)

- 背景 `#0a0e1a`,面板 `#101828`;主霓虹青 `#00e5ff`,副霓虹紫 `#a020f0`,金额绿 `#00ff9d`;金 `#ffc800`、银 `#b8c2d8`、铜 `#cd7f32`;正文 `#dfe6f2`,弱化文本 `#8fa3c8`。
- 标题用电竞感字体(Orbitron/Rajdhani,自托管,不依赖外网字体服务),正文 Inter。
- 电视端按 1920×1080 设计,rem 相对单位缩放适配 4K;数字与名次带霓虹发光(text-shadow/glow)。
- 管理后台使用同色系的低饱和深色主题,以可用性优先,不做重特效。

## 8. 错误处理

- **电视断网/服务器重启**:指数退避重连;期间展示缓存数据 + 角落离线小标记;恢复后全量同步。
- **素材缺失**:无主题曲播默认曲;无照片显示首字母头像;无房源图显示占位图。
- **数据修正**:成交/房源可编辑、删除,榜单自动重算并推送 `data.updated`。
- **配对异常**:配对码错误给出明确提示;过期码自动刷新;解绑后令牌立即失效。
- **音频未解锁**:持续显示启动覆盖层,不静默失败。

## 9. 技术栈

- Next.js(App Router)+ TypeScript + Tailwind CSS + Framer Motion
- 自定义 Node 服务器(`server.ts`)同端口承载 Next 与 `ws` WebSocket
- Drizzle ORM + PostgreSQL;会话 Cookie 管理员登录(bcrypt 密码哈希)
- Cloudflare R2(S3 兼容 API)存储上传文件;本地开发用本地磁盘存储驱动
- 部署:Railway(应用 + PostgreSQL 插件);环境变量注入配置

## 10. 测试策略

- **单元测试(Vitest)**:榜单计算(三指标 × 周期边界 × 并列规则)、庆祝队列(FIFO、打断恢复)、配对码生成与过期。
- **集成测试**:API 路由跑在独立测试数据库上(登录、成交 CRUD、配对、屏幕管理)。
- **端到端(Playwright)**:配对电视 → 录入成交 → 电视收到庆祝事件 → 回轮播的完整链路;断线重连场景。
- 开发过程遵循 TDD。

## 11. 非目标(MVP 明确不做)

- 多租户自助注册、订阅计费(架构预留,不实现)
- 销售员登录账号
- Agentbox 同步适配器的具体实现(只留接口)
- 积分制排名、多屏差异化播放列表(MVP 所有电视播同一内容)
- 金额隐私模式(隐藏电视上的金额)、移动 App、Redis 横向扩容

## 12. 成功标准

- 一台新电视从打开网址到进入轮播 ≤ 1 分钟
- 成交录入后 ≤ 2 秒所有在线电视开始庆祝
- 电视端 7×24 运行无需人工刷新;断网恢复后自动回到正常状态
