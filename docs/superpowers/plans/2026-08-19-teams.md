**Goal:** Type 下拉新增 **Team**:Team 行可挂若干现有 agent 为成员。业绩只能录给 Team 或未归队 agent(归队成员与 staff 一律 400 'Unknown agent');榜单/记分卡只显示 Team 行与未归队个人;Team 成交庆祝展示 Team 名 + 全体 active 成员照片并排;后台 Team 编辑弹窗带 Members 复选区(勾选即改隶属);`docs/import/2026-08-teams.sql` 幂等地把存量三团队行转 Team 并建 7 名成员。成员个人保留生日播报与照片管理。

**Architecture:** 数据层只加一列:`agents.team_id`(text,可空,自引用 FK → agents.id,0004 迁移由 drizzle-kit 生成),`role` 列 zod 层扩为 `'agent' | 'staff' | 'team'`,全部约束在应用层。资格口径收敛到两个共享助手:服务端 `eligiblePerformerWhere`(`src/lib/db/eligibility.ts`,drizzle 条件,5 处录入门统一引用)与客户端纯谓词 `isEligiblePerformer`(`src/lib/domain/eligibility.ts`,admin 三处录入下拉引用),同一口径:`active` 且(`role='team'` 或(`role='agent'` 且 `team_id IS NULL`))。成行资格在 tv/state 组装处过滤(`role ∈ {agent, team}` 且 `team_id IS NULL`),`computeScorecard` 的 role 过滤扩为 agent|team,`computeLeaderboard` 输入无 role 维度不改。membership 只经 `memberIds: string[]` 全量名单进出:服务端事务内 diff(勾选者挂队、原属未勾选者释放),`team_id` 不可直接写。庆祝走既有广播模式:`SaleCelebration` 加可选 `members` 字段,`buildCelebrationPayload` 加可选第 4 参,成员查询助手 `celebrationMembers` 与录入助手同文件;`CelebrationOverlay` 的 `Avatar` 加 `size` 变体复用单照样式。删除语义在既有事务内前插一条成员释放 UPDATE(自引用 FK 也因此必须先释放)。

**Tech Stack:** 与主项目一致(Next.js 15 / React 19 / Drizzle + PGlite/Postgres / Tailwind 3.4 / Vitest / Playwright),零新依赖;一个 schema 迁移(0004,drizzle-kit 生成)。

**契约外决定(notes,spec 未明说、计划敲定):**
1. **spec §6 笔误修正**:schema 生日是单列 `birthday`('MM-DD' text),没有 `birthday_month/birthday_day` 两列;迁移 SQL 用 `birthday = NULL`。
2. **replay 也带 members**:`/api/sales/[id]/replay` 重播 team 成交时同样组装成员名单(与新成交一致;成员按重播时点的现况取)。
3. **PATCH role 变更规则**:(a) 归队成员 role 改为非 'agent'(staff/team)→ 同一 UPDATE 内自动脱队(`team_id=null`);(b) team 行 role 改走时若(diff 后)仍有成员 → 400 'Team still has members',同请求携带 `memberIds: []` 先清空则放行;(c) role 转为 'team' → 服务端自动置 `birthday=null`。
4. **新增校验文案**:`'memberIds is only allowed for team rows'`、`'Team rows cannot have a birthday'`、`'Invalid member'`(成员非本 org role='agent' 行、或含自身)、`'Team still has members'`。成员资格校验不要求 active(UI 只列 active,但挂一个 inactive agent 无害)。
5. **空成员 Team**:庆祝 payload 的 `members` 为空数组时**省略字段**(与个人成交同样式,单头像回落);`memberIds` 可为空数组(允许零成员 Team)。
6. **UI 决定**(Task 2):Team 行也显示 Anthem 字段(spec §4 回退链 "team 行自己的 anthem → org 默认" 所需),即 anthem 显隐条件从 `role === 'agent'` 改 `role !== 'staff'`;Team 行列表隐藏 🎂 按钮;编辑弹窗把 Type 从 Team 改走时随请求发 `memberIds: []`(与删除同语义:成员保留仅脱队);Team 徽标用 gold 配色(区别 Agent 的 neon / Staff 的 muted)。
7. **成员照片并排尺寸**:成员头像 `h-36 w-36`(首字母回落 `text-5xl`),复用现 `Avatar` 组件加 `size: 'lg' | 'sm'` 变体,间距 `gap-6`;标题仍为 Team 名。
8. **迁移 SQL 固定 id**:7 名成员用 `ac200000-0000-4000-8000-000000000001`…`007`(沿用既有 `ac1…`/`ad2…` 字面量风格);按 name NOT EXISTS 判重,`team_id` 用 `(SELECT id FROM agents WHERE name='…' LIMIT 1)` 回查;前置条件为先跑 2026-08-south-scorecard.sql(三团队行由它建出)。
9. **0004 迁移生成方式**:改 schema 后 `npx drizzle-kit generate --name teams`(生成 `drizzle/0004_teams.sql` + meta),不手写迁移文件。
